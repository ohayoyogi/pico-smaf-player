# ホスト通信プロトコル（草案）

この文書は、音源モジュール（RP2040）とホスト（RP2350、ESP32-S3 など）の間で使うプロトコルの草案です。
まだ実装はなく、内容は変わります。

MA 系チップの実レジスタ仕様は公開資料が見当たらないため、このプロトコルはレジスタ互換ではありません。
上流の実装が内部で使うイベント（ノートオン、プログラムチェンジなど）の形を、そのまま外部に出しています。

## 設計の要点

- ホストが送る単位は 2 通り。ファイル単位（`.mmf` を送って再生する）と、イベント単位（ホストが音を直接鳴らす）
- 内部では、ファイル再生もイベント列に展開してから同じ経路で処理する
- 音源モジュールは自分で音声を出力する。ホストとの通信はコマンドだけで、音声データは流れない
- 起動時にホストがプロトコルの版を確認する。版が合わなければ、ホストは音を出さずに動作を続ける

## 物理層

最初は UART で実装します。

- 115,200 bps から始め、1 Mbps まで上げられる設計にする
- 8N1、フロー制御なし
- 音色や `.mmf` の転送が遅いと分かれば、SPI（ホストがマスタ）に移す。フレーム形式は共通にする

## フレーム形式

すべての値はリトルエンディアンです。

| フィールド | 長さ | 内容 |
|---|---|---|
| SYNC | 1 | 固定値 `0xA5` |
| CMD | 1 | コマンド番号 |
| LEN | 2 | ペイロードの長さ（最大 1,024） |
| PAYLOAD | LEN | コマンドごとの内容 |
| CRC | 2 | CMD から PAYLOAD の末尾まで（CRC-16/CCITT-FALSE） |

受信側は、CRC が合わないフレームを捨てて SYNC を探し直します。
モジュールはコマンドごとに、応答フレーム（CMD の最上位ビットを 1 にしたもの）を返します。
応答の先頭 1 バイトが結果コードです。`0` が成功で、それ以外はエラーです。

## コマンド

| CMD | 名前 | ペイロード | 内容 |
|---|---|---|---|
| `0x01` | HELLO | なし | 応答に、プロトコルの版、最大同時発音数、出力サンプルレートを返す |
| `0x02` | RESET | なし | 発音を止め、音色と読み込み済みのファイルを消す |
| `0x10` | VOICE_LOAD | スロット番号 1 バイト、音色 sysex（VM35 または VMA） | 音色を登録する |
| `0x20` | EVENT | イベント 4 バイトの並び（1 個以上） | 即時にイベントを実行する |
| `0x30` | FILE_BEGIN | 総バイト数 4 バイト | `.mmf` の受信を始める |
| `0x31` | FILE_DATA | オフセット 4 バイト、データ | `.mmf` の一部を受け取る |
| `0x32` | FILE_END | なし | 受信を終え、解析する。応答で解析の成否を返す |
| `0x33` | PLAY | ループ回数 1 バイト（0 は無限） | 再生を始める |
| `0x34` | STOP | なし | 再生を止め、発音中の音を消す |
| `0x40` | MASTER_VOLUME | 0 から 127 の 1 バイト | 全体の音量を設定する |
| `0x50` | STATUS | なし | 応答に、再生中か、再生位置（ミリ秒）、出力の途切れ回数を返す |

再生が終わったとき、モジュールは通知フレーム `0xF0`（END_OF_SONG）を自発的に送ります。

### EVENT の 1 件（4 バイト）

| オフセット | 内容 |
|---|---|
| 0 | 種類 |
| 1 | チャンネル（0 から 127） |
| 2 | 値 a |
| 3 | 値 b |

種類は上流の `MaPlayer::Ev` に対応します。

| 値 | 種類 | a | b |
|---|---|---|---|
| 0 | NoteOn | ノート番号 | ベロシティ |
| 1 | NoteOff | ノート番号 | 未使用 |
| 2 | Program | プログラム番号 | 未使用 |
| 3 | BankMsb | 値 | 未使用 |
| 4 | BankLsb | 値 | 未使用 |
| 5 | Volume | 0 から 127 | 未使用 |
| 6 | Pan | 0 から 127（64 が中央） | 未使用 |
| 7 | Expression | 0 から 127 | 未使用 |
| 8 | PitchBend | 下位 7 ビット | 上位 7 ビット |
| 9 | Modulation | 0 から 127 | 未使用 |

上流の `WaveOn`（ADPCM の再生）は、PCM ボイスを載せるかどうかが決まってから追加します。

## 未決事項

- EVENT にタイムスタンプを付けるか。付けなければ、ホスト側の通信の揺れが、そのまま演奏のずれになる
- ホストが音色を送る前に `.mmf` を再生した場合、音色の代わりに使う近似音色（上流の `gmApprox`）を、そのまま使うか
- 応答を待たずに続けて送れる件数（フロー制御）。UART では受信バッファの大きさで決まる
- 2 つの音源（ホスト内蔵の PSG と、このモジュール）の音を混ぜる方法。ホスト側の設計で決める
